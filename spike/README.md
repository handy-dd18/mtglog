# 検証用ページ（T0.1）

本番 PC で V1, V3, V4, V5, V7 を確かめるための使い捨てのコードである。本体（`web/`, `server/`）とは分けてあり、検証が終わったら消してよい。

## 起動（WSL）

```bash
cd spike
uv run server.py            # 127.0.0.1:8765 で待ち受ける
```

Windows の Edge で `http://localhost:8765/` を開く。

## 確かめ方

| ID | 操作 | 「可」とする条件 |
|---|---|---|
| V1 | 「マイクを開く」と「画面全体＋システム音声を共有」を押す。共有の選択画面では「画面全体」を選び、「システム オーディオも共有する」をオンにする | 両方の音量メーターが動き、状態が `live` になる。Teams のテスト通話（「通話の品質を確認」など）の音で、相手側のメーターが動く |
| V3 | 「ウィンドウ＋ウィンドウの音声を共有」を押し、Teams の会議ウィンドウを選ぶ | 選択画面に音声共有のスイッチがある。Teams の音でメーターが動き、別のアプリ（動画再生など）の音では動かない |
| V7 | V1 の状態で「映像トラックを止める」を押す | イベント記録の `audio_after_video_stop` で、音声の `readyState` が `live` のままで、メーターも動き続ける |
| V5 | 両方を開いた状態で「送信を開始」を押し、タブを背景にしたり、Edge を最小化したりして 10 分置く | 受信状況の「欠落」が 0 回で、「最大受信間隔」が 1,000 ms 未満 |
| V4 | V1（または V3）の共有と送信を続けたまま、実際の Teams 会議に 30 分参加する | 会議の音声・映像・Teams の画面共有に異常がない |

結果はページ下部の表に記入し、「結果を保存」を押す。WSL の `spike/results/` に保存される。送信中の受信記録も同じディレクトリに `.jsonl` で残る。
