# 要件: 会議音声のローカル文字起こし

受け入れ基準は EARS 形式で書く。「システム」は取得ページ（Windows の Edge で動く）と文字起こしサーバー（WSL／Docker で動く）を合わせた全体を指す。

## 前提条件

- C-1 Windows 側では独自の実行ファイルやスクリプトを実行しない。Windows 側で動くのは、既存の Edge で開く Web ページだけとする。
- C-2 利用者はヘッドセットを使い、ヘッドセットを Windows の既定の再生デバイスにしておく。会議ツールの出力先もヘッドセットにする。
- C-3 記録の開始と停止は利用者が手動で行う。
- C-4 会議への参加は Teams／Zoom のデスクトップアプリから行う。主催者の設定によってはブラウザーから参加できない Teams 会議があるため、Teams の Web 版を前提にした方式（タブ単位の音声取得など）は使わない。Edge は localhost の取得ページを開くためだけに使い、会議には参加させない。

## REQ-1 使用デバイスの特定

利用者として、会議で使っているヘッドセットのマイクと、相手の声が出ている再生デバイスを、迷わず選べるようにしてほしい。

- REQ-1.1 取得ページを開いたとき、システムはブラウザーが列挙できる入力デバイスの一覧を名前つきで表示しなければならない。
- REQ-1.2 システムは、名前にヘッドセットを示す語（設定で変更可能。既定: `Headset`, `ヘッドセット`, `Headphone`, `ヘッドホン`, `Jabra`, `Poly`, `Logi`）を含む入力デバイスを最初の候補として選択しておかなければならない。該当がなければ既定の入力デバイスを選択しておかなければならない。
- REQ-1.3 システムは、Windows の既定の再生デバイスの名前を、マイクの選択欄と並べて「スピーカー（相手の声の取得元）」として表示しなければならない。それがヘッドセットらしい名前でないときは、C-2 を満たしていない可能性を警告しなければならない（2026-10-22 改訂案）。
- REQ-1.4 利用者が前回選んだマイクがあるとき、システムはそれを次回の初期選択にしなければならない。
- REQ-1.5 記録中に選択中のマイクが取り外されたとき、システムは記録を止めずに利用者へ通知し、別のマイクを選び直せるようにしなければならない。
- REQ-1.6 システムは、REQ-1.3 の表示のそばに、次の 2 点を示さなければならない。スピーカーは取得ページから変更できず、Windows のサウンド設定で変更すること。会議ツールのスピーカーも同じデバイスにすること（2026-10-22 追加案）。

## REQ-2 音声の取得

- REQ-2.1 システムは、利用者が選んだマイクの音を「自分」チャンネルとして取得しなければならない。
- REQ-2.2 システムは、画面共有の仕組みでシステム音声を取得し、「相手」チャンネルとして取得しなければならない。
- REQ-2.3 ブラウザーが特定のウィンドウの音だけを共有できる場合、システムは会議ツールのウィンドウの音だけを「相手」チャンネルとして取得する手順を案内しなければならない（技術方針の V3 の結果で有効にする）。
- REQ-2.4 画面共有でシステム音声が共有されなかったとき（利用者が音声共有を選ばなかった場合を含む）、システムは記録を開始せず、音声共有を有効にして共有し直すよう案内しなければならない。
- REQ-2.5 システムは両チャンネルの音声を 16 kHz・モノラル・16 bit に変換し、共通の時刻基準のタイムスタンプを付けてサーバーへ送らなければならない。
- REQ-2.6 取得ページは、マイクのエコー除去・ノイズ抑制・自動音量調整を、利用者が設定で切り替えられるようにしなければならない（既定: 有効）。
- REQ-2.7 記録中、「相手」チャンネルに音がない状態が、記録の開始時（またはデバイスの変化を検知した時）から続けて一定時間（既定: 2 分。設定で変更可能）経ったとき、システムは取得ページに警告を出さなければならない。警告には、考えられる原因として、会議ツールのスピーカーと Windows の既定の再生デバイスの不一致、システム オーディオの共有のし忘れを示さなければならない。警告は記録を止めず、利用者が閉じられなければならない。「相手」チャンネルに音が戻ったとき、システムは警告を消さなければならない（2026-10-22 追加案）。
- REQ-2.8 記録中、「自分」と「相手」の両方のチャンネルに音がない状態が、一定時間（既定: REQ-2.7 と同じ 2 分。設定で変更可能）続いたとき、システムは記録の途中であっても取得ページに警告を出さなければならない。警告には、考えられる原因として、REQ-2.7 の原因に加えて、マイクが音を拾っていないこと、会議が終わったのに記録を止めていないことを示さなければならない。警告の扱い（記録を止めない、閉じられる、音が戻ったら消す）は REQ-2.7 と同じとする（2026-10-22 追加案）。

## REQ-3 文字起こし

- REQ-3.1 システムは日本語の発話を文字起こししなければならない。言語は設定で変更できなければならない。
- REQ-3.2 システムは無音区間を除き、発話区間ごとに文字起こししなければならない。
- REQ-3.3 発話が終わってから、その発話の文字起こし結果が出力されるまでの遅延は、GPU 利用時に中央値 5 秒以内でなければならない。
- REQ-3.4 各発話の結果は、開始時刻・終了時刻・話者区分（「自分」または「相手」）・本文を持たなければならない。
- REQ-3.5 GPU が使えないとき、システムは CPU 用の設定で動作を続け、その旨をログに出さなければならない。

## REQ-4 出力

- REQ-4.1 システムは記録ごとに 1 つのディレクトリを `output/` の下に作り、文字起こし結果を Markdown と JSON Lines で保存しなければならない。
- REQ-4.2 システムは発話が確定するたびに結果をファイルへ追記しなければならない（異常終了しても確定済みの結果が残る）。
- REQ-4.3 システムは文字起こし結果を、確定した順に取得ページと端末へ表示しなければならない。
- REQ-4.4 録音保存が有効なとき、システムは両チャンネルの音声を WAV で保存しなければならない。録音保存は既定で有効とし、利用者が無効にできなければならない（2026-10-21 改訂）。

## REQ-5 実行基盤

- REQ-5.1 システムは WSL2 上で 1 つのコマンドで文字起こしサーバーを起動し、取得ページの URL を表示しなければならない。
- REQ-5.2 システムは Windows の PowerShell から Docker を使って文字起こしサーバーを起動できなければならない。取得ページは REQ-5.1 と同じものを使う。
- REQ-5.3 取得ページとサーバーの接続が切れたとき、取得ページは再接続を試み、切断中の音声を最大 60 秒分保持して再接続後に送らなければならない。
- REQ-5.4 取得ページのタブが背景にあるときも、システムは取得と送信を続けなければならない。

## REQ-6 プライバシー

- REQ-6.1 システムは音声・文字起こし結果を PC の外へ送ってはならない。外部への通信はモデルの初回ダウンロードに限る。
- REQ-6.2 サーバーの待ち受けは localhost（Docker の場合はホストの 127.0.0.1 へのポート公開）に限らなければならない。
- REQ-6.3 取得ページは外部のスクリプト・フォント・CDN を読み込んではならない。
- REQ-6.4 記録中であることを、システムは取得ページ上に常に表示しなければならない。

## 決定済み事項

- 会議の開始・終了の自動検知は行わず、手動で開始・停止する（C-3）。
- ヘッドセット利用を前提とし、スピーカーからマイクへの回り込み対策は初版の対象外とする（C-2）。
- 相手チャンネルに通知音や他アプリの音が混ざることは、初版では許容する。
- 相手側の複数話者の識別（ダイアライゼーション）は次版の候補とし、初版の対象外とする。
- 会議ツールのミュート状態とは連動しない。ミュート中の発話も「自分」として記録する。本番 PC の Teams では、ミュート状態を外部に知らせる API が使えないため（2026-10-22）。
- 「相手」だけが無音のときの警告（REQ-2.7）は、記録の開始時とデバイスの変化の後だけを対象にする。会議の途中では、自分が話していて相手が黙っている場合と区別できないため。会議の途中のずれは、自分も黙っているときに REQ-2.8 で検知する（2026-10-22 追加案）。
